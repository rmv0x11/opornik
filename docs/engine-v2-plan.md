# Движок v2 — план «мощнейшего движка длинных нард»

*2026-06-10. Синтез: deep-research (16 верифицированных источников, adversarial-проверка
3 голосами на утверждение) + инвентаризация текущего кода (3 read-only агента).
Вопрос: как добиться максимальной силы, вплоть до переписывания с нуля.*

## 1. Диагноз: почему упёрлись (подтверждено с двух сторон)

**Со стороны кода** (`encoding.rs`, `net.rs`, `engine-train`):
- Кодировка — голый TD-Gammon-1992: 196 входов = 24 пункта × 4 унарных признака × 2
  игрока + 4 скаляра (off×2, pip×2). **Ни одного нардового понятия**: ни длины/позиции
  блока, ни «сколько шашек соперника заперто за праймом», ни тайминга/free pips, ни
  правила головы, ни фаз (контакт/гонка), ни распределения дома.
- Обучение — plain SGD TD(0): без TD(λ)-трейсов, без моментума, без регуляризации.
- Один MLP 196→80→3 на все фазы игры.

**Со стороны литературы** — ключевая находка (Papahristou, EvoApplications 2011 + PhD
2015, вердикт верификации 3-0): в **Fevga** (греческий безударный вариант, ближайший
изученный аналог длинных) TD-сеть на чисто сыром кодировании выучила базовую игру, но
**полностью игнорировала праймы** — стратегию, которую эксперты считают сильнейшей в
безударных нардах. Это in vitro наш случай: плато при ER≈0.07, нулевые приросты от
2-ply выбора и 2-ply целей. Усреднение по 21 броску не убирает *систематические*
ошибки value-сети на стратегических (блоковых) позициях — оно убирает только шум.
⚠️ Оговорка: Fevga ≠ длинные нарды (там пункт закрывается одной шашкой; клейм о прямом
тождестве опровергнут 0-3) — перенос по аналогии, не доказанный факт для FSNR.

**Вывод:** лимитирует не алгоритм поиска и не количество партий, а (а) кодировка без
стратегических понятий и (б) TD(0)-цели, которые не несут сигнала о ценности блоков.

## 3. Решение: переписываем «мозг», сохраняем «скелет»

Полное переписывание движка НЕ нужно: правила/генерация ходов/bearoff/поиск/WASM-обвязка
(`engine-core`) верны и быстры, pruning доказан lossless. Переписываются **кодировка,
сеть, обучение и тулинг данных**. Это трек «революция внутри эволюции».

### 3.1. Кодировка v2 (per-phase)
- **Две фазовые сети: contact / race** (как wildbg; класс crashed не нужен — он порождён
  ударами). Диспетчер фазы уже есть по сути: `BearoffTable::is_race`-логика обобщается
  до «нет контакта» (все шашки разошлись).
- **Contact-сеть**: raw 4-входа/пункт/игрока (оставить, но исправить квирк `==3`→`>=3`
  + overflow) **плюс 20–30 экспертных фич длинных нард**, например:
  длина максимального своего/чужого блока (и где он стоит), число последовательных
  пунктов до 6-прайма, число шашек соперника, запертых за блоком, и их pip-глубина;
  тайминг: free pips / запас ходов до развала блока; шашки на голове (свои/чужие);
  pip-разность (есть), гладкость распределения (дисперсия по пунктам), занятость
  своей/чужой домашней четверти, признаки зоны bear-in. Урок TD-Gammon: фичи дают
  больше всего именно при небольшой сети = наш WASM-кейс.
- **Race-сеть**: компактные входы гонки (распределение по своей четверти + pips), цели
  можно частично размечать **точной** bearoff-таблицей (у нас 54 264 состояния) — у
  wildbg такого актива нет.
- **Выходы:** 4-классовый softmax [win-оин, win-марс, lose-оин, lose-марс] с
  CrossEntropy на роллаут-soft-labels (вместо 3 сигмоид + MSE).

### 3.2. Обучение v2 — wildbg-петля (замена TD)
1. Позиции: self-play текущим чемпионом (у нас он есть — старт лучше wildbg'шного
   random), отбор по discrepancy (позиции, где кандидаты расходятся > порога).
2. Роллауты-цели: 1-ply truncated rollouts (наш `rollout_once` + bearoff-усечение),
   1296 игр/позицию (можно 432 на ранних поколениях), на 9–10 ядрах в Rust.
3. Обучение: PyTorch/MPS, минуты на поколение; экспорт весов в наш бинарный формат
   (расширить `net.rs` на 3 скрытых слоя: 300-250-200).
4. Поколение N+1 роллаутит политикой сети N. Повторять, пока mEMG-аналог падает.
5. **Если праймы не возникают из роллаут-целей** — добавить Fevga-3 reward shaping:
   при сформированном ≥X-прайме с запертыми шашками соперника подменять цель
   константой (ранний прайм ≈ оин-победа, поздний ≈ марс). Детектор прайма уже нужен
   как фича — переиспользуется.

### 3.3. Поиск/WASM (минимум работы)
- Expectimax как есть; сузить верхний уровень до top-4 (XG-стиль) → 3-ply дешевеет
  на порядок, остаётся в ~1 с на телефоне даже с сетью ×10 (запас по инвентаризации:
  5–6× на 2-ply + 2–4× от WASM SIMD в `net.rs` forward).
- Фазовый диспетчер: contact-сеть / race-сеть / bearoff-таблица.

### 3.4. Тулинг (этап 0, до всего остального)
- **Генератор размеченного датасета**: `er` уже считает роллаут-эквити и выбрасывает —
  сохранить (позиция, prob-вектор) на диск (`engine-train dataset`).
- **Фиксированный eval-set** с роллаут-метками (стратифицированный по фазам:
  голова/блоки/гонка/bear-off) — журнал mEMG-аналога по поколениям; разбивка ER по фазам.
- CI/SPRT на дуэлях (сейчас только win%+ppg без значимости).
- **Диагностический эксперимент** (закрывает открытый вопрос «почему 2-ply дал ноль»):
  измерить 2-ply прирост при оценке листьев роллаутами вместо сети. Если прирост
  появится — ошибка сети систематическая, рецепт верен.

### 3.5. Чего НЕ делаем (и почему)
- **AlphaZero/Stochastic MuZero** — нет верифицированных свидетельств пользы для
  нардоподобных игр; все топ-движки живут на value+expectimax; на CPU-бюджете это
  худшее соотношение риск/цена. Вернуться, только если wildbg-петля упрётся.
- **Policy-голова** — не нужна (XG/GnuBG/wildbg без неё).
- **Transformer/ResNet** — не нужны на 196–250 входах; MLP 300-250-200 в WASM-бюджете.

## 4. Этапы и критерии успеха

| Этап | Работа | Выход/метрика |
|---|---|---|
| 0. Тулинг | dataset-генератор, eval-set с роллаут-метками, per-phase ER, CI на дуэлях, диагностика «роллаут-листья на 2-ply» | воспроизводимая метрика mEMG-аналога |
| 1. Кодировка v2 | фичи прайма/тайминга/головы, contact/race split, 4-softmax, multi-layer `net.rs` + экспорт из PyTorch | компилится, паритет скорости |
| 2. Петля поколений | self-play → discrepancy-отбор → роллауты 432–1296 → PyTorch → поколение N+1 | mEMG падает поколение к поколению; дуэль ≥55% против текущего чемпиона со значимостью |
| 3. Прайм-проверка | тестовые блок-позиции: строит/держит ли сеть заборы; если нет — Fevga-shaping | качественный чек + eval-set «блоки» |
| 4. Поиск/WASM | SIMD forward, top-4 root pruning, 3-ply в бюджете, фазовый диспетчер | ≤1 с/ход на телефоне |
| 5. Внешняя калибровка | спарринг с LogasAI через `relay`/`agree` (.MAT) | agreement%/ER против внешнего эталона |

Ожидание по источникам: основной прирост даст качество value-сети (роллаут-цели + фичи),
текущий чемпион должен проигрывать v2-сети уже на 1-ply; глубина добирает хвост.

## 5. Открытые вопросы
- LogasAI — чёрный ящик; нужны его реальные партии (план `agree` остаётся в силе).
- Точный состав фич длинных нард — потребуются свои абляции (Fevga-фичи не реплицированы).
- Русскоязычных публикаций/датасетов по длинным нардам не найдено (проверено).
