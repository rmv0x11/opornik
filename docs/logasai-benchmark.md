# Бенчмарк против LogasAI (эталон силы)

LogasAI — сильный движок длинных нард, но только под Windows и без API. Используем
его как **внешний эталон**: запускаем в Windows-VM на Mac (Apple Silicon), играем/
анализируем, выгружаем партии в формате `.MAT`, а наш движок меряет совпадение ходов
и потерю эквити. Это дополняет наш внутренний объективный эталон (роллауты + ER).

> Среда: Apple Silicon (arm64), macOS 26, Rosetta 2 активна, установлены **VMware
> Fusion** и **UTM**. Полный установки Windows не требуется — VM уже есть.

## 1. Windows 11 ARM в VMware Fusion (рекомендуется)

1. **Скачать Windows 11 ARM64 ISO** с официального сайта Microsoft
   (microsoft.com → «Download Windows 11» → раздел **Arm64** disk image). Нужен
   именно **ARM64**-образ (~5 ГБ).
2. **Создать VM**: Fusion → *File → New → Install from disc or image* → выбрать ISO.
   Fusion определит Windows 11 ARM. Ресурсы: ≥4 CPU, ≥8 ГБ RAM, ≥64 ГБ диск.
   vTPM Fusion даёт сам, поэтому требование TPM 2.0 проходит.
3. **Установить Windows**. Для локального аккаунта без интернета на экране региона —
   `Shift+F10` → `OOBE\BYPASSNRO` → Enter (перезагрузит OOBE), либо просто войти под
   Microsoft-аккаунтом. Без активации Windows работает в режиме оценки (водяной знак,
   мелкие косметические ограничения) — для наших целей достаточно.
4. **Установить VMware Tools** (меню *Virtual Machine → Install VMware Tools*) —
   драйверы дисплея/сети, буфер обмена, общие папки.
5. **Эмуляция x86**: Windows 11 ARM (24H2) запускает x86/x64-приложения через
   встроенный эмулятор **Prism** — LogasAI (x86) работает как на обычном ПК.
6. **Общая папка** (VMware Tools → Sharing) — чтобы потом вытаскивать `.MAT`-файлы
   на Mac. Либо drag-and-drop.

### Альтернатива: UTM
UTM (Apple Virtualization) + тот же Windows 11 ARM64 ISO — см. официальный гайд
docs.getutm.app/guides/windows. Тоже бесплатно; Fusion обычно ровнее с драйверами.

## 2. Установка LogasAI внутри Windows

1. Открыть **logasai.ru** (сайт по HTTP, сертификат битый — качаешь на свой риск; VM
   изолирует бинарь). Скачать **LogasAI Game** и **LogasAI Analysis** (есть и Portable).
2. Запустить — x86 идёт через эмуляцию ARM-Windows.
3. Сыграть/проанализировать партии. Game автосохраняет матчи в
   `Документы\LogasAI.Game.MAT.7z`.

## 3. Выгрузка данных для бенчмарка

- Распаковать `LogasAI.Game.MAT.7z`, скопировать `.MAT`-файлы в общую папку → на Mac
  в `models/logasai/` (или любую папку проекта).
- Для разбора по ходам/кубу — модуль **Analysis** (эквити и альтернативы по каждому ходу).

## 4. Что строим на нашей стороне (готовим заранее)

Эти инструменты работают независимо от того, как именно запущен LogasAI:

1. **Импортёр `.MAT`** → наш формат партии/позиции. Парсит броски и ходы длинных нард.
2. **Agreement / ER-бенчмарк**: по каждой позиции из партии LogasAI сравниваем его ход
   с нашим лучшим; считаем % совпадений и среднюю потерю эквити (ER) — та же метрика,
   что во всём мире нард.
3. **Relay-режим** (для ручного спарринга): ты вводишь позицию и бросок — мы выдаём
   лучший ход; ты воспроизводишь его в LogasAI и записываешь исход. Так можно сыграть
   живой матч наш-движок vs LogasAI без автоматизации GUI.

## 5. Реализованный тулинг (готово — `engine-train`)

Всё это уже есть в CLI `engine-train` (модуль `crates/engine-train/src/logasai.rs`,
покрыт юнит-тестами). Сборка: `cargo build -p engine-train --release`, бинарь —
`target/release/engine-train`.

**Формат позиции (одна строка):**
`white=24:13,18:2 black=24:15 turn=W dice=3,1 [white-off=N] [black-off=N] [first]`
— координаты в собственных путях игрока 1..24 (24 = голова, 1..6 = дом); `first`
ставится только для самого первого хода стороны (исключение головы).

1. **Relay** (живой спарринг): читает позиции из stdin, печатает лучшие ходы (эквити +
   win%). Играешь в LogasAI → вводишь его позицию и бросок → повторяешь наш ход.
   ```sh
   echo 'white=24:13,13:1,7:1 black=24:15 turn=W dice=3,1' \
     | engine-train relay --net models/nardy-net.bin --ply 2 --top 4
   ```

2. **Agreement / ER** (метрика силы LogasAI vs наш движок): по списку решений
   (позиция + сыгранный ход `play=…`) считает **% совпадения** с нашим лучшим ходом и
   **ER** (потерю эквити на решение). Ход сопоставляется по итоговой доске
   (свёрнутая нотация эндпоинтов), так что неоднозначный порядок под-ходов в `.MAT`
   не даёт ложных промахов.
   ```sh
   # decisions.txt: по строке на решение
   #   white=… black=… turn=W dice=3,1 play=13/10 7/6
   engine-train agree --net models/nardy-net.bin --file decisions.txt --ply 2
   ```

3. **`.MAT`-импорт**: `agree --mat match.MAT` парсит транскрипт (стандартная
   нотация `  1) 31: 24/20   42: 24/18 13/9`), реконструирует партию ход-за-ходом и
   прогоняет тот же agreement/ER. ⚠️ Точный диалект `.MAT` LogasAI для длинных нард
   **не проверен на реальном экспорте** — парсер сделан под стандартный формат и
   покрыт round-trip-тестом; при первом реальном `.MAT` поправь `parse_mat` в
   `logasai.rs` (он сообщает, на каком ходу нотация не сошлась, а не молча роняет партию).

Подтверждено замерами (`search_bench`, `prune_strength`): forward-pruning
(`ROOT_WIDTH=12`/`SEARCH_WIDTH=8`) на ply-3 **без потери силы** — pruned выбирает тот же
ход, что и FULL (|Δ-эквити|=0.0000 на тестовых бросках; 16/16 решений «SAME»). Поэтому
расширять ширины бессмысленно (только латентность). Реальный прирост даёт глубина и
смена алгоритма обучения — но это крупная работа (см. `training-log.md`). Тулинг выше —
способ объективно измерить, где именно мы уступаем LogasAI, прежде чем в это вкладываться.
