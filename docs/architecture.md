# Архитектура

Цель: современный веб-first продукт для **длинных нард** — игра против сильного ИИ
и людей, анализ позиций («лучший ход» + % выигрыша), обучение и отслеживание
прогресса. Закрываем нишу, где есть сильный движок (LogasAI), но нет современного
веб/мобильного продукта с обучением.

## Принцип: один движок везде

Вся логика, которую больно дублировать (правила, генерация ходов, оценка позиции,
нейросеть, роллауты), живёт **в одном Rust-крейте** `engine-core` и компилируется:

- в **WASM** — мгновенные подсказки и валидация ходов в браузере без сервера;
- в **нативный** код — тренировка self-play, глубокий серверный анализ, CLI.

Это устраняет расхождение правил/оценки между клиентом и сервером — главный
источник багов в таких продуктах. ✔ `engine-core` уже собирается под
`wasm32-unknown-unknown` и не тянет платформенных зависимостей.

## Слои анализа («просчитывать огромное число позиций»)

1. **Генератор ходов** — быстрый, по правилам ФСНР; отдаёт различные результирующие
   позиции (схлопывает перестановки костей). Готово в `moves.rs`.
2. **Нейросеть-оценщик** (TD-Gammon-стиль), обучается self-play **с нуля** именно
   на длинных нардах (готовые сети коротких нард не подходят: другая игра — нет
   битья, одно направление). Вход — кодировка позиции, выход — P(выигрыш) и P(марс)
   на сторону; эквити = взвешенная сумма. Реализовано на **чистом Rust**
   (`net.rs` + `encoding.rs`, тренировка в `engine-train`) — без Python/ONNX, та же
   сеть крутится в WASM. Усиление силой поиска (`search.rs`, n-ply).
3. **Серверные роллауты** (как в GNU BG) — для режима глубокого анализа: политикой
   управляемые, с понижением дисперсии и усечением на входе в эндшпиль (далее).
4. **Точные таблицы эндшпиля** — раскладка выхода 15 шашек по 6 пунктам =
   `C(21,6) = 54 264` позиций (помещается в браузер) → безошибочная оценка гонки и
   точка усечения роллаутов.

Опорные референсы: **wildbg** (Rust + PyTorch→ONNX, чертёж движка), **gym-narde**
(MIT, эталон правил для RL-среды), GNU BG (концептуально: фазовые сети, bearoff-БД,
position/match ID).

## Стек

| Слой        | Выбор                          | Почему |
|-------------|--------------------------------|--------|
| Движок      | **Rust** (`engine-core`)       | один код native+WASM, скорость перебора |
| Фронтенд    | **Svelte 5**                   | лёгкие бандлы, тонкая реактивность для доски |
| Доска       | HTML/CSS-трансформы + SVG-оверлей | модель lichess Chessground; WebGL избыточен |
| WASM-обвязка| wasm-bindgen / wasm-pack, Web Worker | тяжёлый счёт вне UI-потока |
| Бэкенд      | **Go**                         | сильная сторона автора; аккаунты, матчинг, WS, очередь анализа |
| Реалтайм    | coder/websocket + Redis pub/sub| паттерн lila / lila-ws |
| Хранилище   | **Postgres** (+ Redis)         | партии, рейтинги, пазлы, прогресс; Redis — live-state |
| Обучение    | **PyTorch** офлайн (GPU)        | self-play, экспорт весов в клиент |

## Раскладка монорепозитория (целевая)

```
opornik/
  Cargo.toml                  # Rust workspace
  crates/
    engine-core/              # ← готово
      board.rs                #   доска, координаты (две позиц. системы)
      moves.rs                #   генерация ходов (правила ФСНР, head_limit)
      game.rs                 #   GameState, варианты, Rules, исходы
      cube.rs                 #   куб удвоений (удвоение, бивер)
      matchplay.rs            #   матч/деньги, длины, Кроуфорд, Jacoby
      analysis.rs             #   вероятности, ранжирование ходов, решения по кубу
      encoding.rs             #   кодировка позиции для сети (TD-Gammon-стиль)
      net.rs                  #   нейросеть-оценщик (MLP, forward, TD-шаг, веса)
      search.rs               #   n-ply expectiminimax (шанс-узлы по 21 броску)
      eval.rs / ai.rs         #   эвристика + базовый ИИ
    engine-train/             # ← готово: self-play TD тренировка + бенчмарк (native)
    engine-wasm/              # wasm-bindgen обёртка (далее)
    engine-cli/               # нативный анализ / роллауты (далее)
  web/                        # Svelte 5 приложение (далее)
  server/                     # Go: api, ws-gateway, matchmaker, analysis (далее)
  training/                   # PyTorch self-play (далее)
  docs/                       # rules.md, architecture.md, roadmap.md
```

## Обучение и прогресс (чего нет у LogasAI)

- Рейтинг **Glicko-2** игрока и пазлов.
- Разбор ошибок после партии: «сыграно X, лучший Y, −N% эквити», стрелки, подсветка
  бландеров — как в Backgammon Galaxy, но для длинных нард.
- Пазлы из реальных бландеров движка + интервальные повторения (SRS).
- Дашборд прогресса: error-rate (PR), точность по фазам, серии, цели — паттерны
  lichess/Duolingo.

## Нотация

Стандарта для длинных нард нет. Заведём свой формат на базе соглашений GNU BG:
читаемый SGF-подобный лог ходов + компактные base64 Position ID / Match ID,
адаптированные под вариант (15 на голове, одно направление, нет битья, оин/марс).
Это станет форматом хранения, контрактом API анализа и форматом «поделиться позицией».
